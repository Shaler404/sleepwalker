# Схема вики

Этот файл — «конституция» вики. Его читают «сон», критик и компилятор (`harness/compile_wiki.py`),
а правит только человек. Правило из паттерна Karpathy LLM Wiki: сырые данные неизменяемы, вики
пишет модель, человек её читает и задаёт вопросы, схема развивается вместе с проектом.

## 1. Слои данных

```
Sleepwalker/
├── raw/<game>/<session-id>/        # Слой 1. Сырые данные сессии. Только на диске, не в git
│   ├── steps.jsonl                 #   транскрипт: действия с ожиданием (why), заметки, отметки, хэши экранов
│   ├── shots/00001.jpg …           #   кадры в полном разрешении (+ *_m.jpg — то, что видела модель)
│   ├── clips/*.webp, clips.json    #   клипы, нарезанные из записи экрана
│   ├── original.mkv                #   запись экрана; уходит на YouTube и удаляется
│   └── session.json                #   итог: статус, версия игры, клипы, id ролика на YouTube
├── memory/<game>/                  # Рабочая память сессий (пишет рутина «играть»)
│   ├── progress.md                 #   где остановились, что с целями, с чего начать
│   ├── inbox.md                    #   кандидаты в уроки и вопросы, по блоку на сессию
│   ├── sessions.jsonl              #   индекс сессий: вид, статус, итог, YouTube
│   └── state.json                  #   для планировщика: изучена ли игра, когда что было, версия
├── wiki/<game>/                    # Слой 2. Вики игры (пишет только «сон»)
├── skills/<game>/                  # Слой 3. Проверенные навыки (макросы) и их тесты
└── dreams/<YYYY-MM-DD>.md          # Отчёты «снов»: какие сессии разобраны и что изменено
```

`raw/` не попадает в git: кадры и записи слишком тяжёлые, оригиналы видео уходят на YouTube.
Всё остальное лежит в git: история страниц бесплатна, откат — `git revert`.

## 2. Каталог вики одной игры

```
wiki/<game>/
├── index.md            # каталог страниц с однострочными аннотациями
├── log.md              # append-only журнал: ## [2026-10-01] dream | 3 сессии, +2 экрана, обновлён shop.md
├── overview.md         # что за игра, жанр, версия, ядро цикла, первые впечатления
├── ftue.md             # первый запуск и обучение по шагам, с кадрами
├── screens/            # карта UI: одна страница на экран или окно
│   ├── _map.md         #   кто куда ведёт
│   ├── main-menu.md
│   └── shop.md …
├── mechanics/          # правила: основной цикл, боёвка или пазл, ресурсы, случайность, ограничения
├── economy.md          # валюты, источники и стоки, цены, конверсии, жизни и энергия, таймеры
├── monetization.md     # IAP, реклама (форматы, места, награды), баттл-пасс, офферы
├── progression.md      # уровни, рейтинги, разблокировки, мета-прогресс
├── events.md           # календарь LiveOps: активные и прошедшие события, даты, награды
├── versions.md         # версии, даты обновлений, что изменилось
├── open-questions.md   # что неизвестно или не проверено; это цели следующих сессий
├── agent/
│   ├── lessons.md      # уроки агенту: как играть в ЭТУ игру; читаются перед каждой сессией
│   ├── skills.md       # индекс навыков с датой последней успешной проверки
│   └── lint.md         # последний отчёт линтера
├── img/                # кадры: YYYYMMDD-<slug>-<hash8>.webp
└── clips/              # клипы: YYYYMMDD-<slug>.webp (анимированный WebP)
```

Кросс-игровое (паттерны монетизации, типовые экраны, общие уроки агента) живёт в `wiki/_common/`
и ссылается на страницы игр. Корневой `wiki/index.md` — таблица игр.

## 3. Формат страницы

Каждая страница начинается с YAML-фронтматтера:

```yaml
---
game: com.example.game
title: Магазин
type: screen            # overview | ftue | screen | mechanic | economy | monetization | progression | events | versions | questions | agent
version_seen: 1.42.0    # версия игры, на которой страница проверена последний раз
verified_at: 2026-09-28
confidence: 0.8         # 0–1; ниже 0.5 — обязательна пометка «не проверено»
sources: [20260927-231000-onboard, 20260928-001500-event_scan]   # session-id
supersedes: null        # страница, которую эта заменяет (при переименовании)
---
```

Тело — Markdown. Требования:

- Каждый нетривиальный факт заканчивается источником: `[s:20260928-001500-event_scan#37]`
  (сессия и шаг). Факт без источника — нарушение, линтер его помечает.
- Числа (цены, таймеры, награды) — в таблицах, с версией игры, на которой они замечены.
- Кадр: `![подпись](img/20260928-shop-1a2b3c4d.webp)`. Подпись говорит, что на кадре и что важно:
  не «скриншот магазина», а «магазин: 6 паков кристаллов, цены 0.99–49.99 $, таймер оффера 23:59:12».
- Клип: `![подпись](clips/20260928-pervyy-uroven.webp)`, под ним строка
  `*Клип 14 с · [оригинал на YouTube с 3:05](https://youtu.be/<id>?t=185)*`, если оригинал загружен.
- Противоречие не затирается молча: старое утверждение переносится в блок
  `> ⚠️ Ранее (v1.41, 2026-09-20): …`, новое пишется со своим источником.
- Раздел `## Не проверено` в конце страницы — для гипотез.
- Ссылки между страницами относительные (`[магазин](screens/shop.md)`). Внешние — только страница
  игры в Google Play и ролики на YouTube.

## 4. Картинки и клипы

Репозиторий публичный, вики читается прямо на GitHub. Отсюда правила:

- **Без Git LFS и без MP4.** GitHub не проигрывает `<video>` из репозитория: вырезает тег и не
  показывает плеер даже на странице файла (проверено 2026-09-30). Поэтому клип — анимированный
  WebP: он играет в статье по кругу, без звука (запись экрана телефона и так без звука).
- **Кадр**: WebP, длинная сторона не больше 1080 px, качество 85 (`sw.py wiki-img`). Одинаковый
  pHash — тот же файл, дубликаты не создаются.
- **Клип**: до 20 с, длинная сторона 720 px, 12 кадров/с, не больше 8 МБ (`sw.py` режет запись
  сам и при превышении снижает качество). Длинный момент — несколько клипов подряд.
- **Оригинал** записи сессии — на YouTube (`harness/youtube.py`), в репозиторий не попадает. Клип
  ссылается на него с таймкодом.
- **Бережно к размеру**: git хранит всю историю, поэтому медиа добавляются, а не переписываются;
  не больше 5 новых клипов на игру за один «сон». GitHub советует держать репозиторий до 1 ГБ.
- **Личные данные**: ники, почта, аватары, уведомления, окна других приложений и платёжные окна в
  вики не попадают. Такой кадр не берётся; `sw.py mark` и так не даёт отметить кадр не из игры.
- Аннотированные кадры (нумерованные метки) рисует код, не модель; суффикс файла `-annot`.

## 5. Рабочие процессы

### «Сон» (ночью, в ветке `dream/<дата>`)

1. Прочитать `index.md`, `log.md`, `open-questions.md`, `agent/lessons.md` игр с новыми сессиями.
2. Субагент на каждую сессию разбирает транскрипт, кадры, клипы, `progress.md` и `inbox.md`.
3. Оркестратор оставляет только то, за чем стоит повторяемость или явный кадр, и для каждого факта
   решает: новая страница, дополнение, противоречие или уже известно.
4. Страницы правятся точечно, целиком переписывается только новая страница. Фронтматтер
   обновляется: `version_seen`, `verified_at`, `sources`, `confidence`.
5. Обновить `index.md`, `log.md`, закрыть отвеченные вопросы и добавить новые в `open-questions.md`.
6. Слить уроки: одинаковые объединить, устаревшие пометить `(deprecated: v1.42)`; `lessons.md`
   не длиннее 60 пунктов, по убыванию уверенности и свежести.
7. Критик проверяет ветку, владелец мержит pull request или закрывает его.

### Вопросы человека

Ответ собирается из страниц с цитированием источников. Ценные ответы сохраняются как страницы
`analysis/`, например `analysis/retention-hooks.md`.

### Lint (раз в неделю и после большого «сна»)

Записать в `agent/lint.md`:

- страницы без `verified_at` старше 30 дней или с `version_seen` старше текущей версии;
- утверждения без источника; битые ссылки на страницы и медиа; медиа без ссылок;
- противоречия между страницами (цены, названия валют, число уровней);
- страницы-сироты (нет ссылок из `index.md`) и дубли по смыслу;
- вопросы в `open-questions.md`, на которые уже есть ответ на других страницах.

Механику (ссылки, index, slug) линтер исправляет сам, а что перепроверить в игре — ставит задачами
в `open-questions.md`.

## 6. Кто что пишет

| Кто | Пишет | Не делает |
|---|---|---|
| Рутина «играть» | `raw/` через `sw.py`, `memory/<game>/` | не трогает `wiki/` и `skills/` |
| «Сон» (оркестратор и субагенты) | `wiki/`, `skills/`, `dreams/` в ветке `dream/*` | не пишет в `main` и в `memory/` |
| Критик | ничего | не правит, только PASS или FAIL со списком |
| Линтер | механику в `wiki/`, задачи в `open-questions.md` | не добавляет фактов |
| Человек | `games.yaml`, `schema/`, `runbooks/`, мерж PR, комментарии к PR | страницы руками не правит: следующий «сон» их перезапишет. Замечания — комментарием к PR «сна» |
