# Sleepwalker

Агенты играют в мобильные игры, пока вы спите, учатся во «сне» и ведут по каждой игре вики с
кадрами и клипами.

**[Вики →](wiki/index.md)** · [Список игр и целей](games.yaml) · [Руководство](docs/guide.md) ·
[Схема вики](schema/WIKI-SCHEMA.md)

## Как это работает

```
  каждый час                                     раз в сутки
┌─────────────── играть ───────────────┐      ┌──────────────── сон ────────────────┐
│ sw.py next: какая игра и что изучить │      │ субагент на каждую новую сессию     │
│ телефон по USB: кадр → решение → тап │ ───▶ │ оркестратор: паттерны и их частота  │
│ запись экрана, заметки, кадры, клипы │      │ критик: источники, медиа, личное    │
│ memory/<game>: progress.md, inbox.md │      │ pull request ──▶ владелец мержит    │
└──────────────────────────────────────┘      └─────────────────┬───────────────────┘
               ▲                                                │
               └────── уроки, открытые вопросы, вики ◀──────────┘
```

Обе рутины — запланированные задачи Claude Code в приложении на ПК, к которому подключён телефон:
[`runbooks/play.md`](runbooks/play.md) и [`runbooks/dream.md`](runbooks/dream.md). Руками агента на
телефоне служит [`harness/sw.py`](harness/sw.py): он запускает игру, делает кадры и тапы, пишет
экран, режет клипы и ведёт транскрипт сессии.

## Где задать игры и цели

В [`games.yaml`](games.yaml). Рутина перечитывает его перед каждой сессией, поэтому правка на
GitHub или локально действует со следующего часа.

```yaml
defaults:
  goals:                        # общие цели для всех игр
    - "Разобрать экономику: валюты, источники и стоки, цены, таймеры"
games:
  - id: com.maroieqrwlk.unpin   # package из Google Play; игра должна стоять на телефоне
    title: Pull the Pin
    priority: 1                 # меньше — важнее
    goals:                      # цели этой игры, дописываются к общим
      - Разобрать систему ключей и сундуков на карте уровней
  - id: com.nvsgames.snap
    enabled: false              # не играть
```

Вид сессии выбирается сам: `onboard`, пока игра не изучена; `update_diff`, когда телефон обновил
игру; `event_scan` раз в сутки (события, попапы, магазин); `deep_revisit` раз в трое суток (открытые
цели). Вопросы, которые находит «сон», попадают в `wiki/<game>/open-questions.md` и становятся
целями следующих сессий без вашего участия. Настройки машины и телефона (часы работы, лимиты
записи, YouTube) — в `local.yaml`, шаблон [`local.example.yaml`](local.example.yaml).

## На чём система учится

Веса модели не меняются. Учится память — файлы, которые каждая сессия читает перед игрой.

- **Транскрипт сессии** (`raw/<game>/<session>/steps.jsonl`). У каждого действия записано, что агент
  ожидал (`--why`), и что вышло: сменился ли экран, какое приложение на экране. Расхождения,
  застревания и вылеты — сигналы ошибок.
- **Итог сессии от самого агента**: `memory/<game>/progress.md` (что с целями, с чего продолжить) и
  `inbox.md` (кандидаты в уроки со ссылками на шаги).
- **«Сон»** сравнивает все новые сессии всех игр. Урок игры принимается, если повторился в двух
  сессиях или подтверждён кадром; общий урок — если встретился в двух играх. Устаревшее и
  противоречия превращаются в вопросы для перепроверки.
- **Вы.** Мерж или закрытие pull request «сна» и ваши комментарии к нему — самый сильный сигнал.
  «Сон» учитывает только комментарии владельца репозитория.

Результат: уроки (`wiki/<game>/agent/lessons.md`, `wiki/_common/agent-lessons.md`), вопросы-цели,
сама вики, а позже — навыки-макросы, проверенные на телефоне.

## Кто куда пишет

| Зона | Пишет | Как попадает в `main` |
|---|---|---|
| `games.yaml`, `schema/`, `runbooks/`, `harness/`, `CLAUDE.md` | владелец | сразу |
| `raw/<game>/<session>/` | `sw.py` во время сессии | не в git: только на диске |
| `memory/<game>/` | рутина «играть» | коммит в конце сессии |
| `wiki/`, `skills/`, `dreams/` | «сон», только в ветке `dream/*` | после PASS критика и мержа владельцем |

Автор коммита — роль (`Explorer`, `Dreamer`), в трейлерах — сессия и игра: у каждой записи памяти
есть автор, время и откат.

## Картинки и клипы

- Git LFS не используется, MP4 в репозитории нет. GitHub не проигрывает `<video>` из репозитория,
  поэтому клип — анимированный WebP: до 20 с, 720 px, до 8 МБ, играет прямо в статье.
- Кадры — WebP до 1080 px.
- Оригинал записи сессии уходит на YouTube и с диска удаляется; клип ссылается на него с таймкодом.
- Кадры не из игры (уведомления, другие приложения) отметить нельзя; ники, почта и аватары в вики
  не попадают.

Подробно — [`schema/WIKI-SCHEMA.md`](schema/WIKI-SCHEMA.md), раздел 4.

## Запуск

Нужно: ПК с Windows и приложением Claude, телефон Android по USB в режиме разработчика, `adb`,
`ffmpeg`, Python 3.10+ и `pip install pyyaml pillow imagehash adbutils`.

Телефон держите разблокированным, на зарядке и экраном вверх. На зарядке экран не гаснет, а у
Samsung закрытый датчик приближения включает защиту от случайных касаний. На время сессии `sw.py`
включает «Не беспокоить: только будильники» и потом возвращает прежний режим. Сессия не начнётся,
пока вы пользуетесь телефоном.

Проверка вручную:

```
python harness/sw.py next
python harness/sw.py start com.maroieqrwlk.unpin onboard --budget 5
python harness/sw.py tap 540 1200 --why "откроется уровень"
python harness/sw.py end --status ok --summary "проверка"
```

Оригиналы на YouTube — по желанию: инструкция в [`harness/youtube.py`](harness/youtube.py). Пока
проект Google не прошёл аудит, загруженные через API ролики приватные.

## Раскладка

```
games.yaml          игры и цели
local.yaml          настройки машины и телефона (не в git)
runbooks/           инструкции рутин «играть» и «сон»
harness/            sw.py и драйвер телефона; путь через API: explorer, reflect, compile_wiki, scheduler
schema/             схема вики и промпты ролей
docs/guide.md       полное руководство: архитектура, восприятие, память, стоимость, риски
memory/<game>/      рабочая память сессий
wiki/               вики: страница на игру, общие паттерны в _common/
skills/<game>/      проверенные навыки-макросы
dreams/             отчёты «снов»
raw/                сырые записи сессий (не в git)
```

## Почему отдельный репозиторий

- Система работает со списком игр круглосуточно и не связана с кодом какой-либо игры.
- Один репозиторий на вид работы, а не общий на всё: агент читает недоверенный текст с экранов игр,
  поэтому его память не должна пересекаться с другими рабочими заметками.
- Не по репозиторию на игру: «сон» ценен тем, что видит все сессии всех игр сразу.
